# 检索优化工作台

进入 **设置 → 高级检索**。选择神经科学、肿瘤学、重症医学或自己的检索配置后，可以展开来源证据和对应条目。打开 AI 优化时，先在 **设置 → AI** 验证模型连接。对话与试跑记录保存在本机，按配置和会话区分。试跑用到的模型 token 用量与估价可以在 **API 账单 → 检索优化** 查看。

1. 描述想改进的问题，例如「保持已订阅期刊，找回漏掉的脑机接口论文，同时减少新闻误报」。
2. 工作台核验来源近 30 天可观察的发布记录、历史出现过的标识符、当前式与放宽式的差异。每次试跑最多用设定的来源数和轮次。部分覆盖、缺字段和请求异常会单独显示。
3. 给证据示例和试跑差异中的条目标注相关或不相关，再发一条消息继续优化。程序用同一份固定样本回放，并在独立时间窗做复核。相关性标注及其时间覆盖不足时，工作台会保留诊断与样例，等待更多证据。
4. 复核后的候选显示配置差异、增加和漏掉的样例、召回率、相关信息增益、误报和请求成本。开启「允许取舍」时可以审阅非支配的取舍方案。接受后会先核对配置版本，之后可以从同一个会话回滚。

来源可能只有近期 RSS、分页样本或本地会议目录。页面的日期和条目数表示实际采到的证据。会议核验受会议网站和所配置目录的覆盖限制。API 账单中的费用取决于模型返回的用量与已配置的费率；候选质量表的成本以来源请求量计。

浏览器关闭再打开可以回到原会话。服务重启后，后台会继续已排队或已记录为运行中的任务，也可以手动继续曾中断的试跑。取消会在当前网络操作超时或返回后生效。单独的 **运行历史 → 任务详情** 可以恢复或取消正式检索。正式投递有独立记录，已经确认或结果不明确的投递留在任务详情中供核对。

## 让本机其他智能体读取

从源码安装 MCP 额外依赖后，启动所需学科配置的 stdio 服务。

```bash
python -m pip install -e '.[mcp]'
neurodaily --profile oncology mcp
```

MCP 客户端可将 `neurodaily` 设为命令，并传入 `--profile`、配置名和 `mcp` 参数。四个只读工具分别提供运行历史、来源健康、规则归因和已验证试跑结果。草案接受和回滚在工作台完成。
