# 检索优化工作台

进入 **设置 → 高级检索**。选择神经科学、肿瘤学、重症医学或自己的检索配置后，可以展开来源证据和对应条目。打开 AI 优化时，先在 **设置 → AI** 验证模型连接。对话与试跑记录保存在本机，按配置和会话区分。试跑用到的模型 token 用量与估价可以在 **API 账单 → 检索优化** 查看。

1. 描述想改进的问题，例如「保持已订阅期刊，找回漏掉的脑机接口论文，同时减少新闻误报」。
2. 工作台核验来源近 30 天可观察的发布记录、历史出现过的标识符、当前式与放宽式的差异。每个开发窗和复核窗分别采样，来源数和轮次受试跑选项限制。历史标识符核对单独计入请求数。部分覆盖、缺字段和请求异常会单独显示。
3. 在证据区展开各草案的开发试跑或独立复核，可以分页查看实际新增和漏掉的条目并标注相关性。候选使用受影响来源的实际结果，与同一时间窗的固定基线对比。相关性标注不足时，工作台保留诊断，后续可以用新标注重新试跑。
4. 复核后的候选显示配置差异、增加和漏掉的样例、召回率、相关信息增益、误报和请求成本。开启「允许取舍」时可以审阅非支配的取舍方案。应用前会核对配置和相关性标注，之后可以从同一个会话回滚。

来源可能只有近期 RSS、分页样本或本地会议目录。页面的日期和条目数表示实际采到的证据。会议核验受会议网站和所配置目录的覆盖限制。API 账单中的费用取决于模型返回的用量与已配置的费率；候选质量表的成本以来源请求量计。

在 **试跑选项** 中可分别设置每个在线阶段的来源请求上限和时限。基线采集、每轮候选试跑、独立复核各有自己的预算。同一阶段的重定向、重试和标识符查询按实际发出的请求计数。当前阶段的起始时间和用量随任务保存，暂停或重启后继续使用原预算。达到预算后停止发起新请求，正在进行的网络读取可以先返回，未完成的证据会标注在工作台。模型调用的用量仍在 API 账单中查看。

新生成的正式日报以同一检索配置、同一学科和检索方式的上一份成功日报为对照。日报分别列出新增检出的论文、试验状态变化和正式出版记录中的撤稿与更正。来源不可用、覆盖不足和移出时间窗会单独提示。

在本地应用打开新日报，展开条目即可标注相关或不相关。标注保存为该配置的评估样本。新优化试跑的证据区会展示最近标注，优先核验涉及的来源。检索配置仍按工作台的复核和确认流程应用。

## 检查和恢复配置

在 **设置 → 高级检索** 点击 **在本地检查草案**，可以查看来源检索式预览、语法错误、可能缺失的元数据，以及本地历史样本中的匹配统计和失配样例。语法错误会阻止保存。带警告的规则仍可保存。

在 **设置 → 配置文件 → 检索配置版本历史** 选择一个版本，先核对差异，再确认恢复。恢复会追加一条版本记录。定时计划和输出位置仍采用本机设置。正式检索和优化试跑的证据保留相应的配置版本标识。

试跑卡片的 **逐来源试跑对照** 显示每个来源实际观察到的新增、漏掉和请求量。选择 **查看本次优化的模型账单** 可核对每轮模型调用的 token 和费用估算。

## 继续运行和审阅

浏览器关闭再打开可以回到原会话。服务重启后，后台会继续已排队或已记录为运行中的任务，也可以手动继续曾中断的试跑。取消会在当前网络操作超时或返回后生效。单独的 **运行历史 → 任务详情** 可以恢复或取消正式检索。正式投递有独立记录，已经确认或结果不明确的投递留在任务详情中供核对。

## 让本机其他智能体读取

从源码安装 MCP 额外依赖后，启动所需学科配置的 stdio 服务。

```bash
python -m pip install -e '.[mcp]'
neurodaily --profile oncology mcp
```

MCP 客户端可将 `neurodaily` 设为命令，并传入 `--profile`、配置名和 `mcp` 参数。四个只读工具分别提供运行历史、来源健康、规则归因和已验证试跑结果。草案接受和回滚在工作台完成。
